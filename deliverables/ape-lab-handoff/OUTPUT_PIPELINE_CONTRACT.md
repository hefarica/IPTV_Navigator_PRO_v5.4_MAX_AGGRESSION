# APE Output Pipeline Contract

## Layers

```text
LAB.xlsm (calibrated)
  → frontend PM9 / APE profiles
  → typed-array HLS generator
  → list files (_CDN, direct, JIT)
  → VPS metadata/list host
  → ARA metadata + player
  → ONN 4K device
```

## Outputs

| Output | Endpoint / file | Generated by | Notes |
|---|---|---|---|
| HLS list | `/jit/playlist.m3u8` | JIT list builder | 10.573 IDs |
| HLS per channel | `/jit/live/<id>/master.m3u8` | JIT FFmpeg | fMP4/CMAF |
| DASH per channel | `/jit/live/<id>/manifest.mpd` | JIT FFmpeg | CICP/PQ for HDR |
| Metadata | `/jit/live/<id>/manifest.json` | JIT | formats/streams |
| Catalog | `/jit/catalog.json` | JIT | 10.573 channel entries |
| Capabilities | `/jit/capabilities.json` | JIT | formats/codecs/HDR/limits |
| VPS list | `_CDN.m3u8` | prepublishAndGenerateDual | URI VPS, segments direct provider |
| Direct list | generated local | prepublishAndGenerate | provider URLs |

## Format semantics

```text
.M3U8   → HLS, maximum player compatibility
.MPD    → DASH, served by JIT (not fabricated by HLS generator)
HÍBRIDA → HLS + DASH; HLS list and JIT MPD
```

## Transport semantics

```text
DIRECTO = list local + provider URLs
VPS     = list hosted/served by VPS
AMBAS   = URI of channel on VPS + segment URLs direct from provider
          (verified on APE_LISTA_..._CDN)
```

## HDR

```text
4K HDR  = native 3840x2160 HEVC Main10 passthrough (no video re-encode)
1080 HDR= upscaled/encoded 1920x1080 HEVC Main10 with zscale PQ
```

## Buffer guard

```text
entrada >= salida × 1.15
```

The UI blocks generation when measured input does not exceed output by the
15% margin. If no bandwidth sample exists, it warns and does not claim success.

## Honest limits

- HLS is the universal path; DASH is not supported by every IPTV player.
- JIT allows one active channel at a time on the current 3-vCPU VPS.
- 4K HDR is passthrough only when the source is real 4K HDR.
- No guarantee of zero freezes on every device/network; this requires device and
  network E2E testing.
- LCEVC is not available in the installed FFmpeg.

## APE Crystal UHD policy (2026-11-01)

Applied to every JIT channel.

`	ext
HLS tag:  #EXT-X-APE-CRYSTAL-UHD:ENABLED=true
Mode:     NATIVE_4K_HDR | CRYSTAL_UHD_UPSCALE | FHD_HDR10 | FHD_SDR | SDR720_STABLE
Policy:   MAX_IMAGE_FIRST
`

Upscale rule:

`	ext
source 360/480/576/720
→ Lanczos + pad
→ 1920x1080
→ HEVC Main10 HDR10 (PQ)
`

Verified:

`	ext
channel 100: 720x576 → 1920x1080
init: hevc Main 10, level 123, 1920x1080
tag: SOURCE=720x576;TARGET=1920x1080;FILTER=LANCZOS
`

`	ext
channel 5 / 1313573: 1280x720 → 1920x1080
channel 3: 1920x1080 native, no upscale
`

Truth guard: Crystal UHD is a quality policy/metadata plus the real 1080p
HEVC Main10 encode. Native 4K HDR is passthrough only. No fake 4K pixels.

## Crystal UHD 2K update (2026-11-01)

Every source <=1080p now targets:

`	ext
2560x1440
HEVC Main10 HDR10
Lanczos + pad
6.0 Mbps target / 6.6 max
`

Verified init segment:

`	ext
channel 3: 1920x1080 -> 2560x1440, hevc Main 10, level 150
channel 100: 720x576 -> 2560x1440
`

Tags:

`	ext
#EXT-X-APE-CRYSTAL-MODE:CRYSTAL_2K_HDR_UPSCALE
#EXT-X-APE-CRYSTAL-UPSCALE:SOURCE=...;TARGET=2560x1440;FILTER=LANCZOS
`

Native 4K HDR remains passthrough. SDR fallbacks remain 1080/720 for decoder
continuity. HTTP contracts: 23/23 status checks and 14/14 manifest contracts.
Playback performance at 2K on the 3-vCPU VPS is not claimed by these tests.

## 2K status (2026-11-01, measured)

2K was implemented as opt-in APE_2K=1 targeting DCI 2048x1080 HEVC Main10 HDR10.
Measured on the 3-vCPU VPS: only 1 segment per 10s at 2048x1080 and also at 2560x1440.
It is therefore NOT enabled by default; default remains 1920x1080 HDR.

`	ext
APE_2K=1  -> 2048x1080 target (not real-time on current VPS)
default   -> 1920x1080 HDR
`

No current claim of stable 2K live playback.
