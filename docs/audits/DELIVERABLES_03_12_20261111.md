## 1. Entregable 03 — cómo se generó (comando exacto)

No hubo `git add`, no hubo `git add -N`, no hubo commit. El patch se construye **leyendo el árbol de trabajo**,
con un `git diff --no-index` contra `/dev/null` por fichero, concatenando las salidas en binario (sin pasar
por la recodificación de texto de PowerShell, que habría roto los acentos: los ficheros son UTF-8).

```text
LISTA = git ls-files --others --exclude-standard      # 29 ficheros sin seguimiento, ordenados
para cada fichero f de LISTA:
    git diff --no-index -- /dev/null f                # status 1 es lo normal: hay diferencias
concatenar las 29 salidas en binario -> 03_CANARY_JIT_INTEGRATION.patch
```

Equivalente de una línea por fichero (bash), para reproducir a mano:

```bash
for f in $(git ls-files --others --exclude-standard | sort); do
  git diff --no-index -- /dev/null "$f"
done > 03_CANARY_JIT_INTEGRATION.patch   # ojo: bash reescribe bytes; ver nota de encoding
```

**Nota de encoding (importante para reproducir):** en este host, canalizar la salida por PowerShell recodifica
el texto y puede corromper los acentos. El patch entregado se concatenó como **buffers** en Node; el sha256
sólo es reproducible si se hace igual (o con `bash`, que no recodifica).

**El patch no representa un commit.** Son ficheros nuevos añadidos: 29 `new file mode 100644`, 0 borrados,
0 modificaciones de ficheros existentes. Quien lo aplique obtiene los artefactos del equipo, no historia de git.

`docs/ops/RUNTIME_PROVISIONING_PROPOSAL.md` y `docs/policies/SECRETS_IN_BINARIES.md`, y `md_to_pdf.js` cambió

desfase lo detectó; la segunda también, porque otro agente seguía escribiendo. La versión entregada se generó
en **una sola pasada atómica** (leer bytes → hashear → concatenar → calcular digest → **re-chequear el digest
inmediatamente**), así que el patch y su digest son consistentes **por construcción** y el re-chequeo salió
**idéntico** (`fresh_at_generation: true`):

| Campo | Valor |
|---|---|
| Instantánea (UTC) | `2026-11-11T08:17:44Z` |
| Ficheros | 31 |
| `inputs_digest_sha256` | `52255195a3f3b00ef72a54b428c5a8f5d46ea408092723049fefe78f6547bdb3` |
| Re-chequeo inmediato | idéntico (`fresh=true`) |
| Regla del digest | sha256 de las líneas `<path>:<sha256-del-fichero>` en orden lexicográfico, cada una con LF, incluido el LF final |

Para saber si el patch sigue vigente, se recalcula ese digest sobre el árbol actual y se compara con
`artifacts_of_this_delivery.snapshot.inputs_digest_sha256` del recibo. Si difiere, otro agente editó uno de los
