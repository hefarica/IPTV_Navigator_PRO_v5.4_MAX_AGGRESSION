```

- **No hay ningún proceso escuchando en `:3099`.** Comprobado con `ss -tlnp`: la lista de listeners de hoy no incluye 3099.
- El proxy **sí** está configurado y activo: el site incluye `snippets/ape-jit.conf` y ese snippet hace `proxy_pass http://127.0.0.1:3099/`.
- **Consecuencia medida en el log de nginx del propio VPS:**

```
GET /jit/live/3/sdr/master.m3u8
upstream: "http://127.0.0.1:3099/live/3/sdr/master.m3u8"

  Es decir: un cliente real pidió una URL `/jit/` y recibió error porque **el upstream está muerto**.

**Qué invalida esto.** La cadena «Canary define → JIT hereda y ejecuta» no está simplemente sin validar: **el ejecutor no está corriendo**. Los entregables §16 documentan y gobiernan un servicio detenido. Cualquier URL `/jit/live/...` emitida por el generador resuelve a un puerto sin proceso.

**Lo que NO dice esto.** No dice que el fichero no esté: el diff repo↔VPS da **0 cambios**, luego el artefacto está desplegado. Está desplegado y apagado. «Desplegado» ≠ «sirviendo», que es exactamente el error que este repo prohíbe.
